# Bug catalogue

Every entry shipped to a campaign review at least once. The validation gates in SKILL.md Phase 6 exist because of these; if you invent a new check, append it here.

## 1. `flags: "gi"` in `_mod.replaceTxt` — bestiary page dies

`js/utils.js` builds `new RegExp(replace, 'g' + flags)`. A translating agent wrote `"flags": "gi"` (thinking "global + ignore case"); the app produced flags "ggi" → `SyntaxError: Invalid flags supplied to RegExp constructor 'ggi'` → the entire bestiary list rendered empty, with zero visible error text. Found only via a browser sweep + injected `unhandledrejection` collector.

**Check:** `check-mods.cjs` (flags subset of "i"); `grep -rn '"flags": "gi"' data/` must be empty.

## 2. English find-strings in `_mod.replaceTxt` — silent no-op

`_copy._mod.*.replaceTxt.replace` is searched in the BASE entity's text. After the base is translated to French, an English find-string ("the captain", "the mage") matches nothing and the mod silently stops applying — the rendered statblock keeps the base text instead of the copy's substitution.

**Check:** `check-mods.cjs` verifies each find-string occurs in the base's JSON dump (honouring the flags).

## 3. Display text in the source slot of entity tags

`{@creature Main rampante|mains rampantes}` — the translator put the plural display where the source belongs. The renderer reads segment 2 as source, fails to resolve, and renders a dead link. Correct form: `{@creature Main rampante|mm|mains rampantes}`.

**Check:** every 2+-segment entity tag's second segment must be a known source code.

## 4. Stale `_mod` match keys after renaming base entities

`replaceArr.replace` and `removeArr.names` must match the FRENCH names in the base entity (Draconic Ancestry → « Ancêtre draconique », Variable Trait → « Trait variable », Celestial Revelation → « Révélation céleste », Draconic Resistance → « Résistance draconique »…). Each races/subrace variant rename invalidated a batch of keys.

**Check:** `check-mods.cjs` covers replaceTxt; for replaceArr/removeArr, resolve every base name against the pool.

## 5. Positional zip misalignment on reordered data

Merging an EN original against a FR file positionally corrupts when the target reorders entries (young dragons in MM). Identity-based merge (name+source) is the default; fall back to fingerprint matching (page/ac/hp/cr) when names are the thing being translated.

## 6. English detectors without "of" (and other common words)

A residue scanner keyed on the/and/with/has… missed "Warden **of** Waterdeep", "One **of** Manshoon's lieutenants", "A dragonborn priest **of** bronze dragon ancestry". The scanner must include: of, off, was, were, been, who, whom, whose, most, many, other, more, some, any, all, will, must, when, while, which, them, they, into, has, have, had.

## 7. Sidebars regenerated before renames

`gen-contents` maps EN→FR at run time. Any entity rename AFTER regeneration leaves a stale header (Jalester, Laeral both shipped stale once). Rule: renames first, regeneration second, `check-headers.cjs` last.

## 8. Overlapping chunks discovered at assembly

Two WDMM chunks both contained levels 1-3 (~430K of duplicate work). Assert range disjointness in the manifest before dispatching agents.

## 9. `itemGroup` and side-array entries missed

Variant-group parents live in a separate top-level array (`itemGroup`); deities carry a `disease` prop beside `condition`. Scans keyed on one array miss them ("Lantern of Tracking" shipped English).

## 10. Service-worker precache serves ghost data

After any rebuild, the SW serves the previous precache: fixed bugs reappear, new strings look untranslated. Unregister registrations and `caches.delete` every cache before judging any fix. Also: an empty list may just be the source filter — check the served file via `fetch()` in page context before debugging data.

## 11. Executive corrections

The user overrules glossary choices (Hold Breath = « Apnée », never « Rétention d'air »). When corrected, fix repo-wide in the same pass and record in `glossary.md` — the correction applies to every past and future file.

## 12. Half-translated cross-references

An entity renamed in campaign A but referenced by untranslated files in campaign B's scope (e.g. VGM "Gazer" vs WDH « Gazeur ») produces dead links. Resolution checks must run against the GLOBAL pool (all bestiaries), not just the campaign's files.

## 13. Corrupt sidecar maps — validate before repointing

Name sidecars are generated by agents from before/after diffs and positional pairing; they contain errors. The WDH/WDMM `refs-creature-names.json` held positionally-shifted pairs (Magmin→« Mânes », Grick alpha→« Grimlock », Kuo-toa→« Surveillant kuo-toa », Kuo-toa Monitor→« Lamia », Nycaloth→« Pieuvre », Oni→« Orc, œil de Gruumsh ») and `adv-wdmm-5-names.json` held `"Drow": "Drows"`. Applied blindly, a repoint silently rewrote valid identifiers to the WRONG entity.

**Check:** always run `repoint-tags.cjs --pool data/bestiary` — it fail-safe-skips pairs whose FR target collides with another entity's name or disagrees with the entity's actual current name, and lists them for sidecar repair. Exit code 1 when suspects were found.

## 14. verify-structure drifts need triage, not blind fixing

The structural gate reports tag-count differences per string. Triage categories seen in practice: (a) defects — dropped `{@creature}`/broken closing braces (`|25)` instead of `|25}`), fix the data; (b) convention adaptations — DC duplicated after each check name, `{@skill}` tags added where EN had plain text, italics adjustments — accepted deviations, record in the campaign notes; (c) number-count warnings from French comma decimals (« 2,7 » counts as two tokens) — false positives of the number heuristic.
